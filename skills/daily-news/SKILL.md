# daily-news

本人に関係のある外のニュースを毎日3〜5件届ける。「読む価値のある1本」を先頭に置き、本人とどう関係するかを1文で言えない記事は載せない。

## Step 0. 設定を読む（毎回）

同じフォルダの `config.md` を読み、次の値を使う。以下、`{VAULT}` などはその値に読み替える。

| キー | 意味 |
|---|---|
| VAULT | Obsidian vault の絶対パス |
| DIARY_DIR | 日記フォルダ（vault からの相対パス） |
| DIARY_NAME | 日記のファイル名の形（例 `YYYY-MM-DD.md`） |
| DIARY_ANCHOR | 日記の中でリンクを差し込む見出し（この直前に入れる。空なら日記の先頭） |
| NEWS_DIR | ニュースノートの保存先（vault からの相対パス） |
| DATA_DIR | INTERESTS.md・LEARNINGS.md の置き場（vault からの相対パス） |
| EXTRA_SOURCES | 関心を読み取る追加の材料（プロフィールのノート、CLAUDE.md など。任意） |
| PINNED | 日記に出なくても必ず入れるテーマ（任意） |
| LANGUAGE | 出力の言語（既定は日本語） |

`config.md` が無いときは、何も書かずに「README のセットアップを先にしてください」とだけ返して終える。

パスはすべて絶対パスで扱う（定時実行では作業フォルダが決まっていないため）。日付は `date +%Y-%m-%d` で出す。

## Step 1. 前回までの反応を読む

1. `{VAULT}/{DATA_DIR}/daily-news_LEARNINGS.md` を読む（無ければ作る）
2. 直近7日分のニュースノートの `## 本人メモ` 欄を読む。書き込み（「これ良かった」「いらない」「もっと〇〇」など）があれば、LEARNINGS.md に `- YYYY-MM-DD: 〇〇の記事に「…」→ 対応` と1行足し、INTERESTS.md の該当テーマの「拾う／拾わない」に反映する。空なら何もしない（書けと促さない）
3. 会話の中で本人がニュースへの感想を言ったときも同じように LEARNINGS.md に足す

## Step 2. 関心テーマを作る（INTERESTS.md）

`{VAULT}/{DATA_DIR}/daily-news_INTERESTS.md` の `更新日:` が7日以上前か、ファイルが無ければ作り直す。それ以外は今のものを使う。

材料：
1. 直近14日の日記（`{VAULT}/{DIARY_DIR}`）の本文・予定・タスク。出てくるプロジェクト名・固有名詞・繰り返す話題を拾い、回数を数える
2. `EXTRA_SOURCES` に書かれたノート
3. 直近14日に更新された vault 内のノート（ファイル名と見出し程度）

テーマの決め方：
- 最大4テーマ。「本人が直近で時間を使っている」と「外で新しい出来事が起きうる」の両方を満たすものだけ
- `PINNED` のテーマは日記に出なくても残す。INTERESTS.md の「除外」欄にあるテーマは作らない
- 各テーマに書くもの：テーマ名／なぜ今か（日記に何回・どの予定で出たか。根拠のない推測は書かない）／検索クエリ3〜6本／拾うもの／拾わないもの
- 作り直したら、増えた・消えたテーマをファイル末尾の `## 変更履歴` に1行残す

INTERESTS.md の形：

```markdown
# daily-news 関心テーマ

更新日: YYYY-MM-DD

## 本人指定（固定）
## 除外
## 今週のテーマ
### 1. テーマ名
- なぜ今：
- クエリ例：
- 拾うもの：
- 拾わないもの：
## 変更履歴
```

## Step 3. ニュースを集める

- テーマごとに WebSearch を並列で回す。各テーマ1本は `mode: "extended"`（使えれば）で「〇〇 ニュース 今週」の形にする。年月を入れた検索だけだと古い記事が返りやすい
- 候補のURLを WebFetch（または web-fetch エージェント）で開き、公開日・要点・数字を記事本体で確かめる。同じ出来事の一次ソース（省庁・自治体・企業の公式ページ）があればそちらを優先する
- 拾う条件：
  - 公開日を記事本体で確かめられた、過去7日以内のもの。日付が確かめられない記事は載せない
  - 例外：7日より前の公表でも、本人に関係する締切・施行日が7日以内に来るもの（見出しに締切日を入れる）
  - 直近14日のニュースノートに載せた記事・同じ出来事は外す（続報は可）
  - まとめサイト・アフィリエイト記事は使わない
- 合計は最低3件・最大5件。テーマごとに0〜2件
- 7日以内で3件に届かないときは、(1) 期間を14日に広げ、見出しに「（少し前：MM/DD）」を付ける、(2) それでも足りなければテーマの「拾うもの」を一段広げる。どちらも、公開日の確認と「関係」が1文で言えることは同じ条件
- 広げても届かない日は、届いた件数のまま出し、「探したこと」にどこまで広げたかを書く

## Step 4. 書く

ファイル：`{VAULT}/{NEWS_DIR}/YYYY-MM-DD.md`（同じ日の再実行なら置き換える）

```markdown
---
date: YYYY-MM-DD
tags: [ニュース]
---

# YYYY-MM-DD のニュース

## 今日の1本
**見出し**
出典・公開日：媒体名（YYYY-MM-DD）｜[リンク](URL)
- 何が起きたか：記事に書いてあることを1〜2文で（自分の言葉で要約。長い引用はしない）
- 関係：本人のどの作業・予定に、どう関わるか1文

## そのほか
### テーマ名
**見出し**　媒体名（YYYY-MM-DD）｜[リンク](URL)
- 何が起きたか：1文
- 関係：1文

## 探したこと
- テーマ名：検索したクエリ／見つからなければその旨

## 本人メモ
（読んで思ったことがあればここに。次回のテーマ選びに反映されます）
```

書き方：
- 「何が起きたか」は記事に書いてある事実だけ。推測を書くなら「記事は〜としている」と出典に帰す
- 「関係」は具体的に（どのプロジェクトの、どの作業や予定か）。言えないなら載せない
- 「重要」「必読」「衝撃」などの煽り語を使わない

## Step 5. 日記に1行リンクを足す

当日の日記 `{VAULT}/{DIARY_DIR}/{DIARY_NAME}` があるときだけ、読んでから `DIARY_ANCHOR` の見出しの直前に次を入れる。既に `> [!info] 今日のニュース` があればその部分を置き換える。日記が無ければ日記には触らない。

```markdown
> [!info] 今日のニュース（N件）→ [[{NEWS_DIR}/YYYY-MM-DD|開く]]
> 今日の1本：見出し

```

0件の日は `> [!info] 今日のニュース：関係するものはありませんでした → [[{NEWS_DIR}/YYYY-MM-DD|探したこと]]` とする。日記の他の部分は書き換えない。

## Step 6. 終わり方

- git の commit / push はしない
- 会話から呼ばれたときは、今日の1本の見出しと件数をチャットに出し、ノートのパスを添える

## 捏造しない

- URL は検索結果か実際に開いたページのものだけ。推測で組み立てない
- 公開日・数字・固有名詞は記事で確かめたものだけ書く。確かめられなかったら、その記事ごと外す

## 定時実行のとき

- 確認待ちで止まらないように、読むのは Read / Grep / Glob、書くのは Write / Edit を使い、Bash は `date` など1行で終わるものだけにする
- `~/.claude/` の下には書き込まない（許可していても確認が出て止まることがある）。学習ファイルは vault 側の `DATA_DIR` に置く
